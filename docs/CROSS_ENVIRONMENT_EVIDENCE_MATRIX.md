# Cross-Environment Evidence Matrix

**Purpose:** the single authoritative place that resolves "this experiment
looks unfinished in one environment but may exist elsewhere." An experiment
can simultaneously be `PENDING` on the local workstation, `COMPLETE` on
Wulver, and absent from GitHub -- this file is where those three views get
reconciled into one row instead of contradicting each other across docs.

**Provenance of the Wulver-side facts below:** this workstation never
contacts Wulver directly (see repository-wide safety constraints). The
Wulver-side rows in this matrix were relayed by the user from a separately
audited Wulver-side session and recorded here verbatim, with job IDs and
hashes as given. They are labeled `WULVER_ONLY_VALIDATED` rather than
independently verified by this workstation. If you can contact Wulver
directly, re-verify job status/hashes before citing these numbers in a
manuscript.

**Last reconciled:** 2026-08-11.

## Columns

- **Local workstation**: does the artifact/result exist on this machine's disk (any worktree), and is it git-tracked or gitignored-generated?
- **Wulver**: what's known about remote cluster state, per the provenance note above.
- **GitHub/source**: is the *code* (not the result) pushed to `origin`?
- **Authoritative artifact**: the one path/hash that should be cited, whichever environment it lives in.
- **Status**: canonical vocabulary (`FINAL_VALIDATED`, `COMPLETE_DIAGNOSTIC`, `COMPLETE_PARTIAL_SCOPE`, `RUNNING`, `PENDING`, `IMPLEMENTATION_READY`, `SMOKE_ONLY`, `BLOCKED`, `WULVER_ONLY_VALIDATED`, `CONCEPTUAL_BUT_NOT_PRODUCTION_READY`).
- **Promotion needed**: what has to happen for the authoritative artifact to become locally reproducible / on GitHub.

## Notes on apparent contradictions this matrix resolves

- **"LRB/3L-Cache/CACHEUS are `FINAL_VALIDATED`" (older docs) vs. "those jobs are pending" (fresh Wulver audit)** -- both statements are true simultaneously, about *different protocol variants*. The original `reviewer_fairness_v1`-protocol runs for these three baselines completed locally in early August and remain valid supporting evidence under that protocol. A *second*, stricter re-run matched exactly to the corrected cross-family held-out split used for the new 42/42 `evict_value_v1` result is what's pending on Wulver (jobs `1171965`-`1171967`). Do not cite the original-protocol CSVs as if they were run under the corrected split, and do not describe the exact-protocol jobs as "not started from scratch" -- they are a distinct, narrower re-run for comparability, not a redo of everything.
- **"Target degeneracy is single-cell" (most existing docs) vs. "broad 21-cell evidence exists"** -- both true: the *local* diagnostic remains single-cell (`brightkite`/cap64); the *Wulver* campaign (job `1169513`) covers all 21 cells. Existing docs describing degeneracy as single-cell are accurate about local scope but now incomplete about overall project scope -- this matrix is the place that carries the fuller picture until the Wulver result is synced and promoted.
- **"Continuation C1/C2 is `IMPLEMENTATION_READY`"** -- this phrase is still technically accurate (source/tests/config exist and are frozen) but is easy to misread as "ready to launch a full run." It is not: a genuine interface mismatch (`reference_model=`) blocks production execution. Treat `IMPLEMENTATION_READY` + this matrix's `CONCEPTUAL_BUT_NOT_PRODUCTION_READY` note as the accurate combined statement, not `READY_TO_RUN`.
