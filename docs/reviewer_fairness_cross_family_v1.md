# Leave-One-Family-Out Cross-Family Protocol for `evict_value_v1`

Frozen **before** any fold's dataset was built. See
`configs/reviewer_fairness_cross_family_v1.json` for the machine-readable
version.

## Why cross-family (not the fair_v1 approach)

`evict_value_v1_fair_v1` (later same-source-file positions) was rejected:
verified chronologically-later for only 3 of 7 families, unverifiable or
demonstrably non-chronological for the other 4
(`analysis/reviewer_fairness/temporal_order_audit.{json,md}`). Cross-family
training eliminates both risks at once — a held-out family's own records
never appear in its own training/validation data at all, regardless of
timestamps, so neither event-overlap nor temporal-direction can be an
issue for that family.

## Central rule

For every held-out test family `F`: no request from `F` may contribute to
training, validation, hyperparameter selection, feature selection, horizon
selection, seed selection, or early stopping. The model is frozen before
any request from `F` is processed. `F` is evaluated with history
`[0,10000)`, score `[10000,50000)`, exactly 40,000 scored requests, cache
and model state surviving the boundary, metric counters resetting only at
the boundary.

## Deterministic validation rotation

Sort all 7 family identifiers lexicographically:
`brightkite, citibike, cloudphysics, metacdn, metakv, twemcache, wiki2018`.
For the held-out test family at sorted index `i`, the validation family is
the next family cyclically (`i+1 mod 7`). The remaining 5 are training.
This gives every family exactly one turn as validation and never repeats a
test family in its own train/validation set — verified by direct
computation, not by hand:

| Test family | Validation family | Training families |
|---|---|---|
| brightkite | citibike | cloudphysics, metacdn, metakv, twemcache, wiki2018 |
| citibike | cloudphysics | brightkite, metacdn, metakv, twemcache, wiki2018 |
| cloudphysics | metacdn | brightkite, citibike, metakv, twemcache, wiki2018 |
| metacdn | metakv | brightkite, citibike, cloudphysics, twemcache, wiki2018 |
| metakv | twemcache | brightkite, citibike, cloudphysics, metacdn, wiki2018 |
| twemcache | wiki2018 | brightkite, citibike, cloudphysics, metacdn, metakv |
| wiki2018 | brightkite | citibike, cloudphysics, metacdn, metakv, twemcache |

## Global-statistic audit (Section 5 of the task)

Checked directly, not assumed: the only fitted preprocessing statistic
anywhere in the reused pipeline is `StandardScaler` inside the `ridge`
model's `sklearn.Pipeline` (`scripts/train_evict_value_wulver_v1.py`).
`Pipeline.fit(x_train, y_train)` fits the scaler on `x_train` only — for a
cross-family fold, `x_train` is constructed exclusively from the 5
training families, so the scaler never sees validation- or test-family
data. Feature construction itself (`src/lafc/evict_value_wulver_v1.py`)
was also checked for any cross-trace/global statistic (percentile ranks,
corpus-wide normalization, etc.) — none exists; every feature is computed
from a single decision's own locally-observed history. **No code change
was required** to satisfy fold isolation for feature/statistic
construction; isolation is achieved entirely by controlling which traces
are fed into the (unmodified) pipeline per fold.

## Training-family weighting: predeclared decision

The task's stated preference is equal rows per training family (option A).
This was **not implemented** this session: the reused dataset-building
pipeline naturally produces row counts proportional to each family's
request volume and unique-object count, and re-engineering per-family
subsampling to a common budget was out of scope for this session's time
budget. This is recorded as **option B (proportional to requests)**,
predeclared before any fold was built — not a choice made after seeing
results. See `configs/reviewer_fairness_cross_family_v1.json`,
`training_family_weighting`.

## Hyperparameter grid

Reused unchanged from the canonical `heavy_r1` search space (`ridge`,
`random_forest`, `hist_gb`; `train_evict_value_wulver_v1.py`'s own
selection logic — minimum `val_mean_regret`, tie-break `val_mae` then
`val_rmse`). Horizon fixed at 4 (same scope-reduction rationale already
used for `fair_v1`, applying identically and predeclared for every fold —
not re-derived per fold, not chosen after seeing any held-out result).

## Fold manifests

`configs/fair_cross_family_v1/folds/<family>.json` — one per fold, listing
test/validation/training family assignments, trace paths and hashes,
history/score boundaries, feature/label version, model-selection protocol,
seed, and the fold's model output path. Generated by
`scripts/build_evict_value_v1_cross_family_folds.py` before any dataset
construction begins.
